## User-Facing Bugs Found

---

**Bug 1**
- **What the user sees:** The app blocks all responses for the rest of the day, even after midnight.
- **When it happens:** `_hard_cap_hit` is checked in `ask_stream()` before the date-reset logic inside `_track_usage()` runs, so the first message of a new day is still blocked.
- **How bad:** Major
- **File:** `main.py` → `ask_stream()`, hard cap check block
- **Fix hint:** Move the `_hard_cap_hit_date != today` reset logic to before the `hard_cap_active` read in `ask_stream`, not inside `_track_usage`.

---

**Bug 2**
- **What the user sees:** Goals stay stuck in "pending" forever after a restart and can never execute.
- **When it happens:** On startup, goals with `status == "planning"` are set to `"pending"` but have no steps, so the autonomy loop skips them and the planner is never re-triggered.
- **How bad:** Major
- **File:** `main.py` → `NOVAApp.__init__`, goal loading block
- **Fix hint:** Set goals with `status == "planning"` to `"failed"` on restart so users can explicitly resume them.

---

**Bug 3**
- **What the user sees:** A cancelled goal still executes its steps — `/cancel_goal` doesn't actually stop it.
- **When it happens:** Between copying the goal snapshot with `deepcopy` and setting status to `"running"`, a cancel can arrive and be missed because the check happens outside the lock block.
- **How bad:** Major
- **File:** `main.py` → `_autonomy_loop()`, goal status transition block
- **Fix hint:** Re-check `item["status"] != "cancelled"` immediately before setting it to `"running"` inside the same `_goal_lock` block.

---

**Bug 4**
- **What the user sees:** Voice output silently stops working mid-session with no warning.
- **When it happens:** If `pyttsx3` isn't installed, `speak_offline` is `None` and the TTS worker loop silently skips every queued item forever.
- **How bad:** Minor
- **File:** `main.py` → `_tts_worker()`
- **Fix hint:** Print a one-time warning when `speak_offline is None` so the user knows voice is unavailable.

---

**Bug 5**
- **What the user sees:** After typing `/cancel_goal`, then `/resume_goal`, goals with no steps get stuck in `"planning"` again and never resolve.
- **When it happens:** `_resume_goal()` submits a background plan future but the `_on_done` callback double-decrements `_goal_plan_jobs_inflight` when `background_plan` already ran successfully.
- **How bad:** Minor
- **File:** `main.py` → `_resume_goal()`, `_on_done` callback
- **Fix hint:** Only decrement the counter in `_on_done` if the future itself raised — same pattern as the fix already applied in `_add_goal`.

---

**Bug 6**
- **What the user sees:** After switching sessions mid-conversation, the browser keeps operating on the previous session's page.
- **When it happens:** `switch_session()` calls `_browser_close()` but a background goal running `_browser_open` can race against the close.
- **How bad:** Major
- **File:** `main.py` → `switch_session()`
- **Fix hint:** Cancel all running goals before closing the browser on session switch.

---

**Bug 7**
- **What the user sees:** The CLI is locked out for 5 minutes after 5 wrong PINs with no message about how long to wait.
- **When it happens:** After 5 failed PIN attempts, the lockout file is written but the printed message just says "Access Denied" with no timeout hint.
- **How bad:** Minor
- **File:** `interfaces/cli.py` → failed PIN block
- **Fix hint:** Print the remaining lockout duration (300 seconds) in the "Access Denied" message.

---

**Bug 8**
- **What the user sees:** Offline memories written without internet are permanently lost and never synced after reconnecting.
- **When it happens:** `sync_pending()` calls `mem0.add()` and treats any non-exception as success, but if `Mem0Client.add()` returns `{"status": "duplicate"}`, the item is removed from the pending queue even though it was never actually synced to remote.
- **How bad:** Critical
- **File:** `core/memory/memory_router.py` → `sync_pending()`
- **Fix hint:** Only remove items from `_pending_sync` when `mem0.add()` returns `status == "ok"`, not `"duplicate"`.

---

**Bug 9**
- **What the user sees:** Sending an SMS via ADB always fails silently even when the phone number is in the allowlist.
- **When it happens:** `send_sms()` raises `ValueError` when `ALLOWED_PHONE_NUMBERS` is empty, but the dispatcher catches it as a `tool_signature_error` and returns a cryptic JSON error with no user-readable explanation.
- **How bad:** Major
- **File:** `control/adb/adb_client.py` → `send_sms()`
- **Fix hint:** Return a plain error string instead of raising `ValueError` so the dispatcher surfaces a readable message to the user.

---

**Bug 10**
- **What the user sees:** The context trimmer deadlocks and the app freezes when history gets long.
- **When it happens:** `_context_messages()` calls `trim()` which tries to acquire `trimmer._lock`; if the background summarizer is mid-execution holding the same lock on the same thread (RLock re-entry), the second acquire blocks forever.
- **How bad:** Critical
- **File:** `main.py` → `_context_messages()` / `core/memory/context_trimmer.py`
- **Fix hint:** Never pass a `summarizer` lambda that calls back into the LLM engine from within `trim()`; always use the async background path only.
